# AI协作文档框架使用指南 (v2.0)

## 📋 文档说明

本文档是**可复用的文档框架使用指南**,用于指导 AI 和开发人员在新项目中使用这套精简文档架构来管理需求和任务。

**版本**: v2.0

**核心特性**:
- 三层架构设计，结构清晰
- PROJECT-STATUS.md 项目仪表盘，1分钟快速恢复上下文
- 单一数据源原则，避免信息冗余
- 精简模板，减少75%维护负担

---

## 🎯 框架概述

### 核心价值

这套文档框架专为 **AI 协作开发** 设计,具有以下特点:

1. **精简高效**: 三层架构,避免冗余,从6000行精简到2500行
2. **快速恢复**: 通过 PROJECT-STATUS.md 1分钟恢复上下文（vs 原来10分钟）
3. **AI 友好**: 标准化模板,AI 可以快速理解和使用
4. **单一数据源**: 每个信息只在一个地方维护,避免同步问题
5. **可追溯**: 关键决策、重要问题都有完整记录

### 架构层级 (三层)

```
docs/
├── templates/                         # 文档模板库 ⭐ 核心
│   ├── requirements-readme-template.md # 需求管理中心模板
│   ├── project-status-template.md     # ⭐ v2.0核心：项目仪表盘模板
│   ├── requirement-template.md        # 需求文档模板
│   ├── tech-design-template.md        # 技术方案模板
│   ├── task-template.md               # 任务模板（精简版）
│   └── tasks-readme-template.md       # 任务总览模板
│
├── guides/                            # 使用指南 ⭐ 入口
│   ├── 文档框架使用指南.md             # 框架总览（含AI使用指南）
│   ├── 文档更新指南.md                 # ⭐ v2.0核心：3步更新流程
│   └── 快速复用指南.md                 # 复制到新项目
│
└── requirements/                      # 需求管理中心
    ├── README.md                      # 需求索引
    └── REQ-XXX-需求名/                # 单个需求
        ├── 00-PROJECT-STATUS.md       # ⭐ 项目仪表盘（优先阅读）
        ├── 需求文档.md                # 需求文档
        ├── 技术方案设计.md             # 技术方案
        ├── tasks/                     # 任务管理
        │   ├── README.md              # 任务总览（单一数据源）
        │   └── TASK-XXX-任务名.md     # 任务文档
        └── archive/                   # 归档文件夹（可选）
            └── 执行记录-详细日志.md    # 详细日志（可选）
```

## 🤖 AI 使用指南

### 给 AI 的初始化提示词

当开始新项目或新需求时,向 AI 提供以下提示:

```
我们的项目使用精简的三层文档框架来管理需求和任务（v2.0版本）。

**文档框架位置**:
- 模板库: docs/templates/
- 使用指南: docs/guides/文档框架使用指南.md
- 更新指南: docs/guides/文档更新指南.md

**请先阅读以下文档**:
1. docs/guides/文档框架使用指南.md - 了解框架结构
2. docs/guides/文档更新指南.md - 了解更新规范

**当前任务**: [描述你的需求或任务]

**期望**: 请按照文档框架的规范来创建和管理文档。遵循"单一数据源"和"精简记录"原则。
```

### AI 跨会话恢复提示词

当需要继续之前的工作时:

```
我需要继续之前的工作。

请先阅读这个文件：
docs/requirements/REQ-XXX-需求名/00-PROJECT-STATUS.md

然后告诉我：
1. 项目现在是什么状态？（完成度、当前任务）
2. 下一步应该做什么？（待办清单）
3. 有没有阻塞问题？
```

### AI 的核心职责

作为 AI 助手，在使用本框架时的核心职责：

1. **优先创建 PROJECT-STATUS.md**：每个新需求都要先创建项目仪表盘
2. **使用模板**：严格按照 `docs/templates/` 中的模板创建文档
3. **精简记录**：只记录关键决策和重要问题，不记录详细执行流水账
4. **单一数据源**：任务状态只在 `tasks/README.md` 维护，PROJECT-STATUS 引用汇总
5. **遵循更新规范**：完成任务后按照 [文档更新指南.md](./文档更新指南.md) 的3步流程更新

### AI 协作工作流程

当用户提出需求时，AI 的标准响应：

```
我理解你的需求是: [需求概述]

让我为你创建完整的项目文档:

1. 创建项目仪表盘 (00-PROJECT-STATUS.md) - v2.0 核心文档
2. 创建需求文档 (需求文档.md) - 明确目标和范围
3. 创建技术方案 (技术方案设计.md) - 技术选型和架构
4. 分解任务 (tasks/README.md + TASK-XXX.md)
5. 更新索引

开始创建文档...
```

## 📖 详细使用步骤

### 步骤1: 创建新需求

```bash
# 1. 确定需求ID (递增编号)
# 查看已有需求数量,确定新的 REQ-XXX

# 2. 创建需求目录
mkdir -p docs/requirements/REQ-001-需求名称/tasks
mkdir -p docs/requirements/REQ-001-需求名称/archive  # 可选：归档目录

# 3. ⭐ 创建项目现状文档（最重要）
cp docs/templates/project-status-template.md \
   docs/requirements/REQ-001-需求名称/00-PROJECT-STATUS.md

# 4. 使用模板创建需求文档
cp docs/templates/requirement-template.md \
   docs/requirements/REQ-001-需求名称/需求文档.md

# 5. 创建技术方案
cp docs/templates/tech-design-template.md \
   docs/requirements/REQ-001-需求名称/技术方案设计.md

# 6. 创建任务管理索引
cp docs/templates/tasks-readme-template.md \
   docs/requirements/REQ-001-需求名称/tasks/README.md

# 7. 更新需求管理中心（将新需求添加到索引）
# 编辑 docs/requirements/README.md
# - 在需求列表表格中添加新需求行
# - 更新需求状态统计
# - 在需求详情部分添加新需求的概览
```

> 💡 **提示**：如果是在新项目中初始化，需要先使用 `requirements-readme-template.md` 创建 `requirements/README.md`

### 步骤2: 填写需求文档

编辑 `docs/requirements/REQ-001-需求名称/需求文档.md`:

**重点填写章节**:
1. **文档元数据**: 需求ID, 优先级, 状态, 负责人, 日期
2. **一、需求概述**: 核心目标, 业务背景, 需求来源
3. **二、需求范围**: 功能需求, 非功能需求, 边界说明
4. **三、约束条件**: 技术/业务/时间/资源约束
5. **五、验收标准**: 明确的验收条件
6. **六、风险评估**: 识别潜在风险

### 步骤3: 设计技术方案

编辑 `docs/requirements/REQ-001-需求名称/技术方案设计.md`:

**重点设计章节**:
1. **二、技术选型**: 技术栈选择和方案对比
2. **三、架构设计**: 系统架构图, 模块划分, 核心流程
3. **四、详细设计**: 数据模型, API 设计, 核心算法
4. **五、代码隔离策略**: 如何与官方代码隔离

### 步骤4: 分解任务

```bash
# 1. 创建任务管理索引
touch docs/requirements/REQ-001-需求名称/tasks/README.md

# 2. 使用模板创建任务卡片
cp docs/templates/task-template.md \
   docs/requirements/REQ-001-需求名称/tasks/TASK-001-任务名.md

cp docs/templates/task-template.md \
   docs/requirements/REQ-001-需求名称/tasks/TASK-002-任务名.md

# 3. 填写 tasks/README.md
# - 任务总览表格
# - 任务依赖关系图
# - 里程碑定义
```

### 步骤5: 执行任务并更新文档

**详细更新流程参见**: [文档更新指南.md](./文档更新指南.md)

**核心原则**:
- ⭐ 只记录关键决策和重要问题
- ⭐ 遵循"单一数据源"原则
- ⭐ 每次完成任务更新3个文档: `tasks/README.md`、`00-PROJECT-STATUS.md`、`TASK-00X.md`
- ❌ 不记录详细执行步骤流水账

**任务级更新** (完成单个任务时，约10分钟):
1. **Step 1**: 更新 `tasks/README.md` (2分钟)
   - 修改任务状态：`待开始` → `进行中` → `已完成`
   - 填写实际工时和完成日期
   - 更新整体完成度

2. **Step 2**: 更新 `00-PROJECT-STATUS.md` (3分钟)
   - 更新"一分钟速览"章节（当前状态、当前任务、下一步行动）
   - 更新"任务进度总览"表格
   - 更新"待办清单"（勾选完成项，添加新待办）
   - 如有重要决策，更新"关键决策记录"
   - 如有重要问题，更新"重要问题与解决方案"

3. **Step 3**: 更新 `TASK-00X.md` (5分钟)
   - 更新任务元数据（状态、实际开始/完成日期、实际工时）
   - 勾选成功标准
   - 填写关键决策（重要决策才记录）
   - 填写产出物清单（文档产出、代码变更）
   - 记录重要问题（仅重要问题）
   - 填写经验总结（做得好的、需要改进的、可复用的方案）

**需求级更新** (需求状态变更或完成时，约2分钟):
4. **Step 4**: 更新 `requirements/README.md`
   - 更新需求列表表格（状态、完成日期、完成度）
   - 更新需求状态统计
   - 需求完成后填写核心成果

### 步骤6: 更新索引文档

每次创建需求或任务后,更新索引:

```bash
# 更新需求索引
# 1. 更新 docs/requirements/README.md
#    - 需求列表总览表格
#    - 需求状态统计
#    - 需求详情部分（当前状态、核心成果）

# 2. 更新 docs/requirements/REQ-XXX/tasks/README.md
#    - 任务总览表格
#    - 任务状态统计
```

> 💡 **详细更新步骤**: 参见 [文档更新指南.md](./文档更新指南.md) 中的 Step 4

## 🎨 最佳实践

### 命名规范

1. **需求ID**: `REQ-001`, `REQ-002`, ... (三位数字,递增)
2. **需求文件夹**: `REQ-001-需求简短名称` (中文或英文,简洁明了)
3. **任务ID**: `TASK-001`, `TASK-002`, ... (每个需求独立编号)
4. **任务文件**: `TASK-001-任务简短名称.md`

### 优先级定义

- **P0**: 紧急且重要,必须立即处理
- **P1**: 重要但不紧急,近期必须完成
- **P2**: 重要性中等,可以安排到后续迭代
- **P3**: 低优先级,有时间再做

### 状态定义

**需求状态**:
- 待分析 → 设计中 → 开发中 → 测试中 → 已完成 → 已关闭

**任务状态**:
- 待开始 → 进行中 → 已完成 → 已阻塞 → 已取消

### Git 提交规范

```bash
# 文档创建和更新
git commit -m "docs(REQ-XXX): 创建需求文档"
git commit -m "docs(TASK-XXX): 更新任务执行记录"
git commit -m "docs: 更新需求管理中心索引"

# 功能开发
git commit -m "feat(REQ-XXX): 实现XX功能"
git commit -m "fix(TASK-XXX): 修复XX问题"
git commit -m "refactor(REQ-XXX): 重构XX模块"
```

### 文档更新频率

| 文档类型 | 更新频率 | 更新时机 |
|---------|---------|---------|
| PROJECT-STATUS.md | 实时 | 每次完成任务后 |
| tasks/README.md | 实时 | 任务状态变化时 |
| TASK文档 | 按需 | 任务启动和完成时 |
| 需求文档 | 按需 | 需求变更时 |
| 技术方案 | 按需 | 方案调整时 |

## 🔧 常见问题

### Q1: 如何判断是创建新需求还是新任务?

**A**: 判断标准:
- **新需求**: 是一个完整的业务目标,需要独立的技术方案和多个任务
- **新任务**: 是需求下的一个可执行的工作项,2-8小时可完成

**示例**:
- ✅ 需求: "实现用户认证系统"
  - ✅ 任务1: "设计数据库表结构"
  - ✅ 任务2: "实现登录API"
  - ✅ 任务3: "实现注册API"

### Q2: 任务粒度如何把握?

**A**: 建议:
- **单个任务**: 2-8 小时为宜
- **太大**: 超过8小时,建议拆分
- **太小**: 少于1小时,可以合并

### Q3: 如果需求变更怎么办?

**A**: 流程:
1. 在需求文档的 "变更记录" 章节记录变更
2. 更新受影响的章节内容
3. 评估对现有任务的影响
4. 必要时创建新任务或调整现有任务
5. Git 提交注明变更原因

### Q4: 多人协作如何使用?

**A**: 建议:
1. **明确负责人**: 每个需求和任务都指定负责人
2. **状态同步**: 每天更新任务状态
3. **冲突避免**: 不同人负责不同需求或任务
4. **定期Review**: 每周review一次整体进度

### Q5: AI 不按模板生成文档怎么办?

**A**: 解决方法:
1. **明确指令**: 在提示词中明确指定使用哪个模板
2. **提供示例**: 提供 REQ-001 作为参考示例
3. **分步引导**: 不要一次性要求生成全部内容,分章节生成
4. **验证输出**: 生成后检查是否符合模板结构
