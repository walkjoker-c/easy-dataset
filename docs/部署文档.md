# Easy Dataset 部署文档

## Docker 部署

### 前置条件

- Docker 20.10+ 已安装
- Docker Compose 已安装

### 数据库自动初始化机制

本项目采用 **Docker 容器自动初始化数据库** 机制:

1. **首次部署**: 容器启动时自动从镜像内的模板复制初始数据库
2. **后续启动**: 直接使用已有数据库,保留所有数据
3. **数据安全**:
   - 数据库文件 (`prisma/db.sqlite`) 不提交到 Git,避免代码拉取时覆盖数据
   - 通过 Docker volume 挂载实现数据持久化
   - 异常情况 (如目录有文件但缺少数据库) 会拒绝启动并提示错误

> **重要**: `prisma/db.sqlite` 文件完全独立于代码仓库,`git pull` 永远不会影响运行中的数据库。

### 初次部署

**步骤1: 克隆代码**
```bash
git clone git@codehub-cn-south-1.devcloud.huaweicloud.com:b6c759891eee48fcb55ad994808bdfe9/de-dataset.git
cd de-dataset
```

**步骤2: 配置环境变量**
```bash
cp .env.example .env
vim .env  # 修改以下必需配置
```

必须修改的配置项:
- `OBS_ACCESS_KEY` - 华为云 OBS 访问密钥
- `OBS_SECRET_KEY` - 华为云 OBS 密钥
- `OBS_BUCKET` - OBS 桶名称
- `KEYCLOAK_INTROSPECT_URL` - Keycloak 认证地址
- `KEYCLOAK_CLIENT_SECRET` - Keycloak 客户端密钥
- `ADMIN_PASSWORD` - 管理员密码 (至少8位)
- `SUPER_USER_PASSWORD` - 审核员密码 (至少8位)
- `SESSION_SECRET` - Session 密钥 (至少32字符)

**步骤3: 启动服务**
```bash
docker compose up -d
```

服务将在端口 1717 启动。

> **说明**:
> - 首次启动会自动拉取远程镜像 (如可用),通常 1-2 分钟即可启动
> - 如需使用最新本地代码,请使用 `docker compose up -d --build` (构建需要 5-10 分钟)

**步骤4: 验证部署**
```bash
docker compose logs -f  # 查看日志
```

首次启动时,您将看到数据库自动初始化的日志:
```
=== Easy Dataset Database Initialization ===
Database file not found at: /app/prisma/db.sqlite
Prisma directory is empty. Initializing from template...
Database initialized from template!
=== Database Ready! Starting application... ===
```

后续启动时,日志显示直接使用现有数据库:
```
=== Easy Dataset Database Initialization ===
Database file exists: /app/prisma/db.sqlite
=== Database Ready! Starting application... ===
```

测试服务访问:
```bash
curl http://localhost:1717
```

### 版本更新

**步骤1: 备份数据库 (可选但推荐)**
```bash
cd de-dataset
cp prisma/db.sqlite prisma/db.sqlite.backup
```

**步骤2: 拉取最新代码**
```bash
git pull
```

> ✅ **数据安全保证**: `git pull` 不会覆盖 `prisma/db.sqlite`,因为该文件不在 Git 仓库中。您的数据完全安全!

**步骤3: 重新启动服务**
```bash
docker compose down
docker compose up -d --build
```

> **说明**:
> - 使用 `--build` 确保使用最新代码构建镜像
> - 数据库文件通过 volume 挂载,数据完全保留
> - 容器启动时自动检测并使用现有数据库,不会重新初始化

## 环境变量配置说明

### 环境变量分层策略

本项目采用分层环境变量管理策略：

| 文件 | 用途 | Git跟踪 | 是否敏感 | 使用场景 |
|------|------|---------|---------|---------|
| `.env` | 基础配置、默认值 | ✅ 是 | ❌ 否 | 已打包进Docker镜像，提供基础配置 |
| `.env.local` | 敏感信息、环境特定配置 | ❌ 否 | ✅ 是 | 通过volume挂载或环境变量传入，覆盖`.env` |

**优势**：
- ✅ **安全**: 敏感信息不会提交到代码仓库
- ✅ **灵活**: 不同环境使用不同的 `.env.local` 文件
- ✅ **简洁**: 部署时只需配置 `.env.local` 中的敏感信息

**环境变量加载顺序**（后者覆盖前者）：
```
.env (镜像内) → .env.local (挂载/注入) → 系统环境变量
```

SUPER_USER_PASSWORD="your-super-user-password"

# Session密钥 (至少32字符)

## Nginx 反向代理配置

如果需要通过 Nginx 反向代理访问服务，可以使用以下配置。

### 配置步骤

**步骤1: 创建 Nginx 配置文件**

```bash
sudo vim /etc/nginx/conf.d/easy-dataset.conf
```

**步骤2: 写入配置内容**

```nginx
server {
    listen 8080;  # 修改为实际监听端口
    server_name tdp.dev2.aquaintelling.com;  # 修改为实际域名，比如“dev2”换成“test”
    location / {
      proxy_pass http://192.168.0.58:1717;  # 修改为实际应用服务地址（IP:端口）
      proxy_set_header Host $host;
      proxy_set_header X-Real-IP $remote_addr;
      #proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
      #proxy_set_header X-Forwarded-Proto $scheme;
      #proxy_set_header Connection '';
      #proxy_set_header Upgrade $http_upgrade;
      #proxy_set_header Connection Upgrade;
      #chunked_transfer_encoding off;
      #proxy_read_timeout 600;
      #proxy_http_version 1.1;
      #proxy_buffering off;
      #proxy_cache off;
      add_header 'Access-Control-Allow-Origin' 'https://apps.dev2.aquaintelling.com';  # 修改为实际 Keycloak 域名
      add_header 'Access-Control-Allow-Methods' 'GET, POST, OPTIONS';
      add_header 'Access-Control-Allow-Headers' 'DNT,User-Agent,X-Requested-With,If-Modified-Since,Cache-Control,Content-Type,Range';
      add_header 'Access-Control-Expose-Headers' 'Content-Length,Content-Range';
    }
  }
```

> **注意**：需要修改的配置项：
> - `listen 8080` - 修改为实际监听端口
> - `server_name tdp.dev2.aquaintelling.com` - 修改为实际域名
> - `proxy_pass http://192.168.0.58:1717` - 修改为实际应用服务地址（IP:端口）
> - `add_header 'Access-Control-Allow-Origin' 'https://apps.dev2.aquaintelling.com'` - 修改为实际 Keycloak 域名

**步骤3: 测试配置**

```bash
sudo nginx -t
```

**步骤4: 重载 Nginx**

```bash
sudo nginx -s reload
```

## 常见问题 (FAQ)

### Q1: 数据库文件会被 Git 覆盖吗?

**A: 不会**

`prisma/db.sqlite` 已添加到 `.gitignore`,不会提交到 Git 仓库。执行 `git pull` 时:
- ✅ 不会下载或覆盖该文件
- ✅ 现有数据完全保留
- ✅ 无需任何额外操作

### Q2: 首次部署时如何初始化数据库?

**A: 容器自动初始化**

无需手动操作,容器启动时会自动执行以下步骤:
1. 检测 `/app/prisma/db.sqlite` 是否存在
2. 不存在则从镜像内的模板 (`/app/prisma-template`) 自动复制
3. 初始化完成后启动应用

查看日志可以看到初始化过程:
```bash
docker compose logs -f
```

### Q3: 如何升级数据库结构?

**A: 后续提供专门的升级脚本**

当数据库 schema 变更时,会提供专门的迁移脚本。当前机制仅负责初始化,不处理升级。

### Q4: 数据库文件存储在哪里?

**A: 宿主机的项目目录**

数据库文件位于:
- **宿主机**: `./prisma/db.sqlite` (项目根目录)
- **容器内**: `/app/prisma/db.sqlite` (通过 volume 挂载)

两者实际是同一个文件,容器内的修改会立即同步到宿主机。

### Q5: 容器启动失败,提示数据库相关错误怎么办?

**A: 检查以下情况**

如果看到错误日志:
```
ERROR: Database file missing but prisma directory is not empty!
```

**解决方案**:
1. 检查 `prisma/` 目录内容:
   ```bash
   ls -la prisma/
   ```
2. 如果只有 `schema.prisma` 等配置文件,没有 `db.sqlite`:
   - 删除 `prisma/` 目录下的所有文件
   - 重新启动容器,自动从模板初始化
3. 如果有重要数据:
   - 检查是否有备份文件 (如 `db.sqlite.backup`)
   - 恢复备份后重启容器

### Q6: 如何手动备份/恢复数据库?

**A: 直接复制文件**

**备份**:
```bash
cp prisma/db.sqlite prisma/db.sqlite.backup-$(date +%Y%m%d-%H%M%S)
```

**恢复**:
```bash
docker compose down
cp prisma/db.sqlite.backup prisma/db.sqlite
docker compose up -d
```

### Q7: 多环境部署如何管理数据库?

**A: 每个环境独立维护**

- **开发环境**: `dev-server/de-dataset/prisma/db.sqlite`
- **测试环境**: `test-server/de-dataset/prisma/db.sqlite`
- **生产环境**: `prod-server/de-dataset/prisma/db.sqlite`

每个环境的数据库文件独立,互不影响。`git pull` 只更新代码,不影响数据库。
