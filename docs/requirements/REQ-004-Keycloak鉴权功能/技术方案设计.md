## 一、方案概述

### 1.1 背景说明
当前系统存在严重的安全风险:用户可以从浏览器F12获取项目URL,在新标签页或其他浏览器中直接访问其他用户的数智员工训练数据,造成数据泄露风险。需要集成Keycloak鉴权系统,实现基于用户身份的访问控制。

公司平台已在Cookie中携带JWT Token (`Cookie: Authorization=<token>`),可直接使用。

### 1.2 设计目标
- **核心目标**: 实现三步验证流程(管理员验证 + Token合法性验证 + 权限验证),防止越权访问
- **性能目标**: Token验证响应时间 < 200ms (缓存命中), < 500ms (首次验证)
- **质量目标**: 向后兼容现有项目,所有验收标准通过
- **可维护性目标**: 严格遵循代码隔离规范,未来可跟随官方版本升级

### 1.3 设计原则
- **安全优先**: 采用严格模式,强制要求Token或管理员Session
- **代码隔离**: 能不改官方代码就不改,优先新增文件,必须修改时使用CUSTOM标记
- **向后兼容**: 现有项目(createdByUserId为NULL)仍可访问
- **简单可靠**: V1.0实现核心功能,避免过度设计

## 二、技术选型

### 2.1 技术栈
| 技术类型 | 选择方案 | 版本 | 理由 |
|---------|---------|------|------|
| Session管理 | iron-session | ^8.0.x | Next.js官方推荐,零配置,安全加密,App Router兼容 |
| HTTP客户端 | node-fetch (内置) | 内置于Node.js 18+ | 无需额外依赖,原生支持,与项目环境兼容 |
| Token缓存 | node-cache | ^5.1.2 | 轻量级,易用,支持TTL自动过期 |
| 数据库ORM | Prisma | ^6.6.0 | 项目已使用,保持一致性 |

### 2.2 方案对比

#### Session管理方案对比

**方案A: iron-session**
- **优点**:
  - Next.js官方推荐
  - 零配置,开箱即用
  - 自动加密,安全可靠
  - 支持App Router
  - 文档完善,社区活跃
- **缺点**:
  - 内存存储,重启后丢失(可接受,管理员重新登录即可)
- **适用场景**: 中小型应用,管理员会话管理

**方案B: next-auth**
- **优点**:
  - 功能强大,支持OAuth
  - 内置Keycloak Provider
- **缺点**:
  - 过度复杂,需要配置Provider
  - 与需求不符(需求是本地密码登录,不是OAuth流程)
  - 引入额外依赖和学习成本
- **适用场景**: 需要OAuth登录流程的应用

**方案C: express-session**
- **优点**:
  - 成熟稳定
  - 支持Redis存储
- **缺点**:
  - 需要额外配置Express中间件
  - Next.js App Router集成复杂
  - 需要Redis依赖(可选)
- **适用场景**: 传统Express应用

#### HTTP客户端方案对比

**方案A: node-fetch (内置)**
- **优点**:
  - Node.js 18+ 内置,无需安装
  - 标准Fetch API,易用
  - 体积小,性能好
- **缺点**:
  - 功能相对简单
- **适用场景**: 简单HTTP请求

**方案B: axios**
- **优点**:
  - 功能丰富,支持拦截器
  - 自动JSON转换
- **缺点**:
  - 项目已有axios依赖,但调用Keycloak introspect接口足够简单,不需要拦截器等高级功能
- **适用场景**: 复杂HTTP请求场景

#### Token缓存方案对比

**方案A: node-cache**
- **优点**:
  - 轻量级,易用
  - 支持TTL自动过期
  - 支持get/set/del等基础操作
  - 无需额外配置
- **缺点**:
  - 内存存储,重启后丢失(可接受,重启后重新验证即可)
- **适用场景**: 简单缓存场景

**方案B: lru-cache**
- **优点**:
  - LRU算法,内存占用可控
- **缺点**:
  - 功能复杂,本需求无需LRU
- **适用场景**: 缓存数据量大时

**方案C: Redis**
- **优点**:
  - 分布式缓存,支持多实例
  - 持久化
- **缺点**:
  - 需要额外部署Redis服务
  - 配置复杂,运维成本高
  - 对本需求过度设计(单实例部署)
- **适用场景**: 分布式部署,多实例共享缓存

### 2.3 最终选择
- **Session管理**: iron-session
- **HTTP客户端**: node-fetch (内置)
- **Token缓存**: node-cache

**理由**:
- iron-session最适合Next.js App Router,安全可靠,零配置
- node-fetch无需额外依赖,满足introspect调用需求
- node-cache轻量级,满足Token缓存需求,避免过度设计

### 3.2 模块划分

#### 模块1: Keycloak验证模块 (`lib/custom/auth/keycloak.js`)
- **职责**: 调用Keycloak introspect接口验证Token合法性,提取用户ID
- **核心函数**:
  - `introspectToken(token)` - 调用introspect接口,返回 `{ active, sub, exp }`
- **依赖**: node-fetch, 环境变量配置

#### 模块2: Session管理模块 (`lib/custom/auth/session.js`)
- **职责**: 管理管理员登录Session
- **核心函数**:
  - `getSession(req)` - 获取Session数据
  - `saveSession(req, data)` - 保存Session数据
  - `destroySession(req)` - 销毁Session
- **依赖**: iron-session

#### 模块3: Token缓存模块 (`lib/custom/auth/cache.js`)
- **职责**: 缓存Token验证结果,减少Keycloak调用
- **核心函数**:
  - `getCachedToken(tokenHash)` - 获取缓存的Token验证结果
  - `setCachedToken(tokenHash, data, ttl)` - 缓存Token验证结果
  - `clearCache()` - 清空缓存
- **依赖**: node-cache

#### 模块4: 三步验证中间件 (`lib/custom/auth/middleware.js`)
- **职责**: 核心鉴权逻辑,协调上述模块,执行三步验证
- **核心函数**:
  - `authMiddleware(req, projectId)` - 执行三步验证,返回 `{ authorized, userId, status?, error? }`
- **依赖**: Keycloak模块, Session模块, Token缓存模块, Prisma

#### 模块5: 鉴权配置模块 (`lib/custom/config/auth.config.js`)
- **职责**: 统一管理鉴权相关环境变量配置
- **导出**: authConfig对象
- **依赖**: 环境变量

#### 模块6: 管理员登录API (`app/api/admin/login/route.js`)
- **职责**: 处理管理员密码验证,设置Session
- **路径**: `/api/admin/login`
- **方法**: POST
- **依赖**: Session模块

#### 模块7: 管理员登录页面 (`app/admin/login/page.js`)
- **职责**: 提供管理员密码输入界面
- **路径**: `/admin/login`
- **依赖**: 前端UI组件

### 3.3 核心流程

#### 流程1: 用户通过employeeId首次访问 (自助创建项目)
```
用户访问: GET /api/projects/employee/ABC123
   ↓
步骤1: authMiddleware检查Session
   ├─ req.session?.isAdmin === true ?
   │   └─ YES → return { authorized: true, userId: 'admin' } → 跳到步骤6
   └─ NO → 继续步骤2
   ↓
步骤2: 从Cookie提取Authorization Token
   ├─ 无Token → return { authorized: false, status: 401 }
   └─ 有Token → 继续步骤3
   ↓
步骤3: 验证Token (Keycloak introspect)
   ├─ 计算tokenHash = SHA256(token)
   ├─ 检查缓存: getCachedToken(tokenHash)
   │   ├─ 命中 → userId = cachedData.userId → 跳到步骤5
   │   └─ 未命中 → 继续步骤4
   ↓
步骤4: 调用Keycloak introspect接口
   ├─ POST /token/introspect
   ├─ 返回: { active: true/false, sub, exp }
   ├─ active === false → return { authorized: false, status: 401 }
   ├─ active === true → userId = sub
   └─ 缓存结果: setCachedToken(tokenHash, { userId, exp }, ttl)
   ↓
步骤5: 权限验证 (跳过,项目尚未创建)
   └─ 返回 { authorized: true, userId }
   ↓
步骤6: 查询项目 (通过externalId)
   ├─ 未找到 → 创建新项目
   │   └─ createdByUserId = userId (从Token的sub字段)
   └─ 找到 → 返回现有项目
   ↓
步骤7: 返回项目数据或重定向
```

#### 流程2: 用户B尝试访问用户A的项目 (越权访问)
```
用户B访问: GET /api/projects/PROJECT_ID (用户A创建的项目)
   ↓
步骤1: authMiddleware检查Session
   └─ req.session?.isAdmin === false → 继续步骤2
   ↓
步骤2-4: Token验证 (同流程1)
   └─ 提取 userIdB (用户B的ID)
   ↓
步骤5: 权限验证
   ├─ 查询项目: createdByUserId = userIdA
   ├─ 判断: userIdB != userIdA
   └─ return { authorized: false, status: 403, error: '无权访问此项目' }
   ↓
步骤6: 返回403 Forbidden
```

#### 流程3: 管理员登录并访问所有项目
```
管理员登录: POST /api/admin/login { password: "xxx" }
   ↓
步骤1: 验证密码
   ├─ password === process.env.ADMIN_PASSWORD ?
   │   ├─ YES → 设置Session: req.session.isAdmin = true → 返回200
   │   └─ NO → 返回401
   ↓
管理员访问任意项目: GET /api/projects/PROJECT_ID
   ↓
步骤2: authMiddleware检查Session
   ├─ req.session?.isAdmin === true
   └─ return { authorized: true, userId: 'admin', bypass: true }
   ↓
步骤3: 直接返回项目数据 (绕过Token验证和权限验证)
```

### 4.2 API设计

#### API 1: Keycloak introspect调用
**文件**: `lib/custom/auth/keycloak.js`

**函数签名**:
```javascript
/**
 * 调用Keycloak introspect接口验证Token
 * @param {string} token - JWT Token字符串
 * @returns {Promise<Object>} - introspect响应
 * @throws {Error} - 调用失败时抛出错误
 */
export async function introspectToken(token)
```

**实现示例**:
```javascript
import { authConfig } from '../config/auth.config';

export async function introspectToken(token) {
  try {
    const response = await fetch(authConfig.keycloak.introspectUrl, {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: new URLSearchParams({
        token: token,
        client_id: authConfig.keycloak.clientId,
        client_secret: authConfig.keycloak.clientSecret,
      }),
    });

    if (!response.ok) {
      throw new Error(`Keycloak introspect failed: ${response.status}`);
    }

    const data = await response.json();
    return data; // { active: true/false, sub, exp, ... }
  } catch (error) {
    console.error('[Keycloak] Introspect error:', error.message);
    throw error;
  }
}
```

**响应格式**:
- Token无效: `{ "active": false }`
- Token有效: `{ "active": true, "sub": "8e7180cc-...", "exp": 1789031494, ... }`

#### API 2: 三步验证中间件
**文件**: `lib/custom/auth/middleware.js`

**函数签名**:
```javascript
/**
 * 三步验证中间件
 * @param {Request} req - Next.js请求对象
 * @param {string|null} projectId - 项目ID (可选,用于权限验证)
 * @returns {Promise<AuthResult>}
 *
 * AuthResult:
 * - { authorized: true, userId: string, bypass?: boolean }
 * - { authorized: false, status: 401|403, error: string }
 */
export async function authMiddleware(req, projectId = null)
```

**实现逻辑** (详细伪代码):
```javascript
export async function authMiddleware(req, projectId = null) {
  // ========== 步骤1: 管理员Session验证 ==========
  const session = await getSession(req);
  if (session?.isAdmin === true) {
    console.log('[Auth] Admin session detected, bypassing token verification');
    return { authorized: true, userId: 'admin', bypass: true };
  }

  // ========== 步骤2: Token合法性验证 ==========
  // 2.1 从Cookie提取Token
  const token = req.cookies.get('Authorization')?.value;
  if (!token) {
    console.warn('[Auth] No token found in Cookie');
    return { authorized: false, status: 401, error: '未授权访问,请重新登录' };
  }

  // 2.2 检查缓存
  const tokenHash = createHash('sha256').update(token).digest('hex');
  const cached = getCachedToken(tokenHash);
  let userId;

  if (cached) {
    console.log('[Auth] Token cache hit');
    userId = cached.userId;
  } else {
    // 2.3 调用Keycloak introspect
    console.log('[Auth] Token cache miss, calling Keycloak introspect');
    try {
      const introspectResult = await introspectToken(token);

      if (!introspectResult.active) {
        console.warn('[Auth] Token is not active');
        return { authorized: false, status: 401, error: 'Token无效或已过期' };
      }

      userId = introspectResult.sub;

      // 2.4 缓存结果
      const ttl = Math.min((introspectResult.exp - Date.now() / 1000), 30 * 60); // 最长30分钟
      setCachedToken(tokenHash, {
        userId: userId,
        exp: introspectResult.exp,
        cachedAt: Date.now()
      }, ttl);
      console.log(`[Auth] Token cached for ${ttl}s`);

    } catch (error) {
      console.error('[Auth] Keycloak introspect failed:', error.message);
      return { authorized: false, status: 503, error: '鉴权服务不可用,请稍后重试' };
    }
  }

  // ========== 步骤3: 权限验证 ==========
  if (!projectId) {
    // 无需权限验证(如创建项目时)
    return { authorized: true, userId };
  }

  // 3.1 查询项目创建者
  const project = await db.projects.findUnique({
    where: { id: projectId },
    select: { createdByUserId: true }
  });

  if (!project) {
    return { authorized: false, status: 404, error: '项目不存在' };
  }

  // 3.2 权限判断
  const createdBy = project.createdByUserId;

  if (createdBy === null) {
    // 现有项目,允许所有用户访问
    console.log('[Auth] Legacy project (createdByUserId=NULL), access granted');
    return { authorized: true, userId };
  }

  if (createdBy === 'admin') {
    // 只有管理员可访问
    console.warn('[Auth] Admin-only project, access denied');
    return { authorized: false, status: 403, error: '此项目仅管理员可访问' };
  }

  if (createdBy === userId) {
    // 用户访问自己的项目
    console.log('[Auth] User accessing own project, access granted');
    return { authorized: true, userId };
  }

  // 用户尝试访问他人项目
  console.warn(`[Auth] Permission denied: user ${userId} tried to access project owned by ${createdBy}`);
  return { authorized: false, status: 403, error: '无权访问此项目' };
}
```

    if (!password) {
      return NextResponse.json(
        { error: '请输入密码' },
        { status: 400 }
      );

        { status: 401 }
      );
    }
  } catch (error) {
    console.error('[Admin] Login error:', error);

#### Token缓存优化
```javascript
// lib/custom/auth/cache.js
import NodeCache from 'node-cache';
import { createHash } from 'crypto';

// 创建缓存实例
const tokenCache = new NodeCache({
  stdTTL: 600, // 默认10分钟
  checkperiod: 120, // 每2分钟检查过期
  useClones: false, // 不克隆对象,提升性能
});

/**
 * 获取缓存的Token验证结果
 * @param {string} tokenHash - Token的SHA256哈希值
 * @returns {Object|null} - 缓存数据或null
 */
export function getCachedToken(tokenHash) {
  return tokenCache.get(tokenHash) || null;
}

/**
 * 缓存Token验证结果
 * @param {string} tokenHash - Token的SHA256哈希值
 * @param {Object} data - 缓存数据 { userId, exp, cachedAt }
 * @param {number} ttl - 缓存时间(秒)
 */
export function setCachedToken(tokenHash, data, ttl) {
  tokenCache.set(tokenHash, data, ttl);
}

/**
 * 清空缓存 (用于测试或配置变更)
 */
export function clearCache() {
  tokenCache.flushAll();
}

/**
 * 获取缓存统计信息
 */
export function getCacheStats() {
  return tokenCache.getStats();
}
```

**缓存TTL计算逻辑**:
```javascript
// Token有效期 vs 最大缓存时间,取最小值
const tokenExpInSeconds = introspectResult.exp - Math.floor(Date.now() / 1000);
const maxCacheTtl = 30 * 60; // 30分钟
const ttl = Math.min(tokenExpInSeconds, maxCacheTtl);

// 确保TTL > 0
if (ttl > 0) {
  setCachedToken(tokenHash, data, ttl);
}
```

#### Keycloak调用优化
- 使用HTTP Keep-Alive连接池 (fetch默认支持)
- 超时时间设置: 5秒
- 失败重试: 不重试 (避免雪崩,直接返回503)

```javascript
// lib/custom/auth/keycloak.js
export async function introspectToken(token) {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), 5000); // 5秒超时

  try {
    const response = await fetch(authConfig.keycloak.introspectUrl, {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: new URLSearchParams({
        token: token,
        client_id: authConfig.keycloak.clientId,
        client_secret: authConfig.keycloak.clientSecret,
      }),
      signal: controller.signal,
    });

    clearTimeout(timeoutId);

    if (!response.ok) {
      throw new Error(`Keycloak introspect failed: ${response.status}`);
    }

    return await response.json();
  } catch (error) {
    clearTimeout(timeoutId);
    if (error.name === 'AbortError') {
      throw new Error('Keycloak introspect timeout');
    }
    throw error;
  }
}
```

## 七、安全设计

### 7.1 安全威胁分析
| 威胁类型 | 风险等级 | 影响 | 防护措施 |
|---------|---------|------|---------|
| Token泄露 | 高 | 攻击者可冒充用户访问 | httpOnly Cookie, secure Cookie, sameSite: strict |
| Session劫持 | 中 | 攻击者劫持管理员Session | iron-session加密, httpOnly Cookie, Session有效期限制 |
| 管理员密码泄露 | 中 | 攻击者获得管理员权限 | 环境变量配置, 强密码要求, 不hardcode |
| Keycloak服务不可用 | 中 | 所有请求失败 | Token缓存降级, 优雅错误处理 |
| 日志泄露敏感信息 | 低 | Token/密码泄露 | 日志脱敏, 不记录完整Token |

### 7.2 安全措施

#### 认证机制
- **普通用户**: Keycloak JWT Token (Cookie传递)
- **管理员**: 密码登录 + Session验证 (iron-session加密)

#### 授权机制
- **三步验证**: 管理员Session → Token合法性 → 权限匹配
- **最小权限原则**: 用户只能访问自己创建的项目

#### 数据加密
- **Session加密**: iron-session自动加密Session数据
- **HTTPS**: 生产环境强制HTTPS (secure Cookie)

#### 防注入
- **Prisma ORM**: 自动防SQL注入
- **输入验证**: 验证projectId, employeeId格式

#### Cookie安全配置
