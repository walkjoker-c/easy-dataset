## 一、方案概述

### 1.1 背景说明
当前系统仅支持从本地文件系统上传文件,用户需要先从OBS下载文件到本地,再上传到系统,操作繁琐。本方案旨在在text-split页面集成OBS文件浏览和导入功能,简化用户操作流程,并实现文件状态自动管理(pending→completed)。

### 1.2 设计目标
- **核心目标**: 实现从OBS对象存储直接选择和导入文件的功能
- **性能目标**:
  - OBS文件列表加载时间 < 3秒
  - 支持批量文件下载(3-5个并发)
  - 单个文件下载进度实时反馈
- **质量目标**:
  - 代码遵循REQ-001代码隔离最佳实践
  - 单元测试覆盖率 ≥ 70%
  - 集成测试覆盖主要用户场景
- **可维护性目标**:
  - 组件化设计,模块解耦
  - 配置化管理(OBS凭证、环境等)
  - 完善的错误处理和日志记录

### 1.3 设计原则
- **隔离性原则**: 新增代码放在custom目录,最小化对官方代码的修改
- **可扩展原则**: 支持多种OBS服务(华为云OBS、AWS S3、MinIO等)
- **用户友好原则**: 操作流程与本地上传保持一致,学习成本低
- **安全性原则**: OBS凭证加密存储,不在前端暴露敏感信息

## 二、技术选型

### 2.1 技术栈
| 技术类型 | 选择方案 | 版本 | 理由 |
|---------|---------|------|------|
| OBS SDK | 华为云OBS SDK (esdk-obs-nodejs) | v3.x | 官方SDK,稳定可靠,中文文档完善 ✅ |
| 前端UI | Material-UI | v5.x | 项目现有UI库,保持一致性 |
| 后端API | Next.js API Routes | - | 项目现有架构,无需额外服务 |
| 文件下载 | Node.js Streams | - | 支持大文件,内存占用低 |
| 状态管理 | React Hooks + useState | - | 轻量级,符合项目现有模式 |

### 2.2 OBS SDK方案对比

#### 方案A: 华为云OBS SDK
- **优点**:
  - 官方SDK,针对华为云OBS优化
  - 文档完善,中文支持好
- **缺点**:
  - 仅支持华为云OBS,不支持其他S3兼容存储
  - 社区相对较小
- **适用场景**: 明确只使用华为云OBS的场景

#### 方案B: AWS SDK for JavaScript v3 ⭐ 推荐
- **优点**:
  - S3兼容协议,支持华为云OBS、AWS S3、MinIO等多种存储
  - 社区活跃,文档完善
  - 模块化设计,按需引入,包体积小
  - 支持Node.js和浏览器环境
- **缺点**:
  - 配置相对复杂(需要正确设置endpoint、region等)
- **适用场景**: 需要兼容多云存储的场景(推荐)

#### 方案C: MinIO JavaScript Client
- **优点**:
  - 专为MinIO设计,也支持S3兼容存储
  - API简洁,易于使用
  - 轻量级
- **缺点**:
  - 功能相对简单,不如AWS SDK完善
  - 社区规模小于AWS SDK
- **适用场景**: 主要使用MinIO的场景

### 2.3 最终选择
**选择**: 方案A - 华为云OBS SDK ✅ (技术负责人决策)

**理由**:
1. **明确的服务商**: 项目数据存储在华为云OBS,使用官方SDK最稳定
2. **官方支持**: 华为云官方维护,针对自家OBS服务优化
3. **文档完善**: 中文文档完善,技术支持响应快
4. **功能充足**: 满足项目需求的所有功能(文件列表、下载、移动)

  - `listObjects(bucket, prefix)`: 列出对象
  - `downloadFile(bucket, key, localPath)`: 下载文件
  - `moveObject(bucket, srcKey, dstKey)`: 移动对象
- **依赖**: AWS SDK for JavaScript v3

### 3.3 核心流程

#### 流程1: OBS文件浏览流程
```
用户点击"上传文件"
   ↓
弹出UploadSourceSelectDialog(选择"本地"或"OBS")
   ↓ (选择OBS)
判断项目是否有externalId
   ↓
   ├─有externalId:显示环境选择(dev/test/prod)→自动构建路径
   └─无externalId:显示路径输入框(完整路径或agentType)
   ↓
用户确认环境/路径
   ↓
前端调用 GET /api/obs/list?env=test&agentType=xxx
   ↓
后端构建OBS路径,调用SDK listObjects
   ↓
返回pending和completed两个文件夹的文件列表
   ↓
前端展示OBSBrowserDialog(两个标签页:pending、completed)
   ↓
用户选择文件(单选/全选)
   ↓
用户点击"确认"
```

#### 流程2: OBS文件下载流程
```
用户在OBSBrowserDialog中选择文件并点击"确认"
   ↓
选中的文件信息传递到UploadArea(与本地文件一样展示)
   ↓
用户点击"上传"按钮
   ↓
前端调用 POST /api/obs/download (批量文件keys)
   ↓
后端遍历文件列表,逐个下载到临时目录
   ├─使用Stream API避免内存溢出
   ├─实时返回下载进度(SSE或轮询)
   └─下载失败记录错误,继续下载其他文件
   ↓
所有文件下载完成,返回本地临时路径列表
   ↓
前端使用临时路径调用现有的文件处理流程(handleUploadSuccess)
   ↓
文件处理完成
```

#### 流程3: 文件移动流程
```
文件处理完成后
   ↓
前端调用 POST /api/obs/move (文件keys)
   ↓
后端遍历文件列表,逐个执行移动操作
   ├─copyObject(srcBucket, srcKey, dstBucket, dstKey)
   ├─deleteObject(srcBucket, srcKey)
   └─操作失败记录错误日志,不影响主流程
   ↓
返回移动结果(成功/失败列表)
   ↓
前端显示移动结果提示(可选)
```

### 4.3 核心算法

#### 算法1: OBS路径构建
- **用途**: 根据项目信息和用户输入构建OBS文件路径
- **复杂度**: O(1)
- **伪代码**:
  ```javascript
  function buildOBSPath(env, agentType, folder) {
    // 验证参数
    if (!['dev', 'test', 'prod'].includes(env)) {
      throw new Error('Invalid env');
    }
    if (!agentType) {
      throw new Error('AgentType is required');
    }
    if (!['pending', 'completed'].includes(folder)) {
      throw new Error('Invalid folder');
    }

    // 构建路径
    const path = `env=${env}/messageType=conversation_data/agentType=${agentType}/${folder}/`;
    return path;
  }
  ```

#### 算法2: 批量文件并发下载
- **用途**: 并发下载多个OBS文件,控制并发数
- **复杂度**: O(n), n为文件数量
- **伪代码**:
  ```javascript
  async function downloadFilesWithConcurrency(files, concurrency = 3) {
    const results = [];
    const errors = [];

    // 分批下载
    for (let i = 0; i < files.length; i += concurrency) {
      const batch = files.slice(i, i + concurrency);
      const promises = batch.map(file =>
        downloadSingleFile(file)
          .then(result => results.push(result))
          .catch(error => errors.push({ file, error }))
      );
      await Promise.allSettled(promises);
    }

    return { results, errors };
  }
  ```

## 六、安全设计

### 6.1 安全威胁分析
| 威胁类型 | 风险等级 | 影响 | 防护措施 |
|---------|---------|------|---------|
| OBS凭证泄露 | 高 | 数据泄露、非法访问 | 凭证加密存储、不在前端暴露、使用临时凭证 |
| 路径注入攻击 | 中 | 访问非授权文件 | 路径参数验证、白名单机制 |
| SSRF攻击 | 中 | 访问内网资源 | endpoint白名单、URL验证 |
| 文件下载滥用 | 低 | 资源耗尽、费用增加 | 下载频率限制、文件大小限制 |

### 6.2 安全措施

#### 6.2.1 凭证安全
- **环境变量存储**: OBS凭证存储在`.env.local`文件,不提交到Git
- **后端访问**: OBS SDK只在后端(API Routes)使用,前端不直接访问OBS
- **临时凭证(可选)**: 使用STS Token机制,降低凭证泄露风险

#### 6.2.2 输入验证
```javascript
// 路径参数验证
function validateOBSParams(env, agentType) {
  // 环境白名单
  const allowedEnvs = ['dev', 'test', 'prod'];
  if (!allowedEnvs.includes(env)) {
    throw new Error('Invalid environment');
  }

  // agentType格式验证(UUID或特定格式)
  const agentTypeRegex = /^[a-zA-Z0-9\-]+$/;
  if (!agentTypeRegex.test(agentType)) {
    throw new Error('Invalid agentType format');
  }

  return true;
}
```

#### 6.2.3 访问控制
- **项目隔离**: 只能访问当前项目关联的OBS路径
- **文件夹限制**: 只能访问pending和completed文件夹
- **文件类型验证**: 只下载允许的文件类型(.md, .txt, .docx, .pdf, .epub)

#### 6.2.4 资源限制
```javascript
// 下载限制配置
const OBS_DOWNLOAD_LIMITS = {
  maxFilesPerRequest: 20,      // 单次最多下载20个文件
  maxFileSizeBytes: 100 * 1024 * 1024, // 单个文件最大100MB
  maxConcurrency: 3,           // 最多3个并发下载
  requestTimeout: 30000        // 30秒超时
};
```

### 8.1 部署架构
```
生产环境:
┌─────────────────────────┐

         │ HTTPS
```

```bash
# 步骤1: 安装依赖
npm install @aws-sdk/client-s3

cat >> .env.local <<EOF
OBS_ACCESS_KEY=your-access-key
```

### 8.3 回滚方案
- **回滚触发条件**:
  - OBS集成功能严重故障,影响正常使用
  - 文件下载错误率 > 50%
  - 系统整体稳定性下降
- **回滚步骤**:
  1. 停止服务: `pm2 stop easy-dataset`
  2. 切换到上一个稳定版本: `git checkout previous-stable-tag`
  3. 重新构建: `npm run build`
  4. 启动服务: `npm run start`
  5. 验证回滚成功: 检查本地上传功能正常
- **回滚验证**: 确认本地文件上传功能可用,OBS相关功能被禁用或降级

### 9.3 运维手册

#### 常见问题1: OBS连接超时
**症状**: API请求返回超时错误
**原因**: 网络问题或OBS服务不可达
**解决方案**:
1. 检查网络连接: `ping obs.cn-north-4.myhuaweicloud.com`
2. 检查OBS凭证是否过期
3. 检查防火墙规则
4. 增加超时时间配置

#### 常见问题2: 文件下载失败
**症状**: 下载文件时报错"文件不存在"
**原因**: OBS路径错误或文件已被删除
**解决方案**:
1. 检查路径构建逻辑是否正确
2. 在OBS控制台验证文件是否存在
3. 检查文件权限配置

#### 常见问题3: 文件移动失败
**症状**: pending文件未移动到completed
**原因**: OBS写权限不足或completed目录不存在
**解决方案**:
1. 检查OBS凭证的写权限
2. 手动创建completed目录
3. 查看错误日志获取详细信息
