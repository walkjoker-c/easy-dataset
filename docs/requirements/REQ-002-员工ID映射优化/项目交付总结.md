## 🎯 需求回顾

### 核心问题

当前员工API使用 `name` 字段同时承担两个职责:
1. 作为外部系统的映射ID (employeeId)
2. 作为项目列表的展示名称

这导致:
- 项目列表显示长字符串(如 `employee-123e4567-e89b-12d3-a456-426614174000`),无法区分
- 用户无法修改项目名称,否则会破坏外部系统映射
- name字段唯一性约束限制了多用户场景

### 解决方案

添加专用的 `externalId` 字段用于外部系统映射,释放 `name` 字段为用户可编辑的展示名称:

- **externalId**: 存储外部系统ID (如employeeId),唯一索引
- **name**: 用户可见的项目名称,允许重复,可自由编辑

## 🐛 问题与解决

### 问题1: Next.js 编译错误

**错误**: "Server actions must be async functions"

**原因**: 在 `lib/custom/employee-project.js` 文件顶部添加了 `'use server'` 指令,但 `generateFriendlyProjectName()` 是纯函数

**解决**: 移除 `'use server'` 指令,该文件是普通服务器端工具函数,不是 React Server Actions

**影响**: 无,修复后功能正常

---

### 问题2: URL编码问题

**问题**: curl 测试中文参数时失败

**原因**: shell 脚本中直接使用中文字符未进行URL编码

**解决**: 使用 `curl --data-urlencode` 参数自动编码

**影响**: 仅影响测试脚本,实际代码无问题
