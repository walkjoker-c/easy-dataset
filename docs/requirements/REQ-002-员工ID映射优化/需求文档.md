## 一、需求概述 ⭐

### 1.1 核心目标

优化员工API项目创建和映射机制,通过添加专用的 `externalId` 字段解耦外部系统ID与项目展示名称,提升用户体验和系统可维护性。

### 1.2 业务背景

- **现状**:
  - 项目通过 `/api/projects/employee/[employeeId]` API以微服务方式嵌入公司平台
  - 当前使用项目 `name` 字段存储 `employeeId` 实现项目映射
  - `employeeId` 是一个特别长的字符串(如 UUID 或类似格式)

- **问题**:
  1. **用户体验差**: 项目列表展示长串ID,用户无法直观区分不同项目的数据集内容
  2. **命名冲突**: `name` 字段职责混乱,既作为外部系统映射ID,又作为用户展示名称
  3. **维护困难**: 不允许用户修改项目名导致用户无法设置有意义的项目名称
  4. **功能受限**: 允许修改项目名会破坏映射关系,导致下次API调用无法找到对应项目

- **期望**:
  - 外部系统通过API访问时能准确定位到对应项目
  - 用户可以为项目设置和修改有意义的中文名称
  - 项目列表清晰展示项目用途,便于管理多个数据集项目

### 1.3 需求来源

- **提出人**: 用户 (amx)
- **提出日期**: 2025-11-08
- **业务场景**: 公司平台通过员工ID调用API创建和访问训练数据集项目,用户需要在数据集管理平台清晰区分多个员工的项目

## 二、需求范围

### 2.1 功能需求

#### 核心功能1: 添加外部ID字段
- **输入**: 数据库Schema定义
- **输出**: Projects 模型新增 `externalId` 字段
- **约束**:
  - 字段类型: String (可选,允许为null)
  - 唯一性约束: `@unique` (同一externalId不能重复)
  - 索引: 添加索引提升查询性能
  - 向后兼容: 现有项目 externalId 为 null

#### 核心功能2: 修改员工API映射逻辑并支持自定义名称
- **输入**:
  - employeeId (URL参数,必需)
  - name (查询参数或Body,可选) - 自定义项目名称
  - description (查询参数或Body,可选) - 项目描述
- **输出**: 重定向到对应项目页面
- **约束**:
  - 支持GET和POST两种方法
  - 通过 `externalId` 字段查找项目(而非 `name`)
  - 创建项目时设置 `externalId = employeeId`
  - 如果传入name参数,使用自定义名称;否则自动生成
  - 默认名称格式: `员工项目-{后8位ID}-{日期}` (如 "员工项目-174000-20251108")
  - 如果项目已存在且传入name,更新项目名称
  - 保持原有重定向逻辑不变

#### 核心功能3: 解除项目名称编辑限制和唯一性约束
- **输入**: 用户编辑项目名称
- **输出**: 更新项目 `name` 字段
- **约束**:
  - `name` 字段可自由编辑,不影响外部系统映射
  - 允许不同项目使用相同名称(移除API层唯一性检查)
  - 普通用户创建的项目 `externalId` 为 null
  - 仅员工API创建的项目有 `externalId` 值

#### 扩展功能
- 在项目设置页面展示 `externalId` (只读,仅当存在时显示)
- 员工API支持双接口: GET(兼容性) + POST(规范性)

### 2.2 非功能需求

- **性能要求**:
  - externalId 字段添加唯一索引,查询性能≤10ms
  - 数据迁移对现有项目无影响

- **安全要求**:
  - externalId 不暴露在前端URL中(仍使用项目ID)
  - 只读展示,防止用户篡改映射关系

- **可用性要求**:
  - 向后兼容,现有项目不受影响
  - 普通用户创建项目流程无变化

- **兼容性要求**:
  - 兼容 Prisma ORM 数据迁移机制
  - 兼容现有 SQLite 数据库

### 2.3 边界说明

#### 包含范围 ✅
- 数据库Schema添加 `externalId` 字段
- 员工API添加POST方法,支持GET/POST双接口
- 员工API支持自定义name参数(查询参数或JSON body)
- 员工API支持更新已存在项目的名称
- 移除 `app/api/projects/route.js` 中的name唯一性检查
- 自定义代码层封装 (lib/custom/)
- 项目设置页面UI调整(可选展示externalId)
- 相关文档更新

#### 不包含范围 ❌
- 不修改项目ID生成规则
- 不涉及其他API端点的修改
- 不修改项目删除和更新的核心逻辑
- 不涉及权限和认证机制的调整
- 不进行大规模UI重构

- **向后兼容**: 不能破坏现有普通用户创建项目的流程
